# 能力广场与每日推荐

[English](capability-plaza.md) | [简体中文](capability-plaza.zh-CN.md)

能力广场把 amux 已有的用法整理为 4 类、16 项能力，每项提供两个可编辑示例。
本指南收录全部 32 个示例，并说明使用条件。你需要已接入的飞书机器人；
新手引导、能力广场和推荐开关面向该机器人的负责人，在与机器人的私聊中使用。
尚未接入时，先完成[第一个机器人教程](../tutorials/first-feishu-bot.zh-CN.md)。

## 从新手引导开始

在私聊中发送 `/amux`，选择“新手引导”。首次识别负责人时也会提供欢迎卡。

1. 选择连续对话或独立话题：前者继续同一段对话，后者为不同工作保留各自的聊天历史。
   聊天历史分开仍可能共用工作区文件，文件与执行隔离需要另行配置。
2. 选择可用的运行引擎、模型和思考强度。思考强度始终展开，表示模型回答前投入的推理程度；
   首次未设置时默认采用模型实际支持的最高档位，已有明确选择会保留。更强的思考可能耗时更久。
3. 选择并预览一个示例任务，修改时间、链接或材料后再发送。日历等能力在执行时通过所需
   Skill 按需授权，向导里没有单独的“连接日历”步骤。
4. 在“继续探索”中选择已有专家、添加 Git 专家库，或填写名字、职责、Git 地址和 Skill
   需求来创建专家。一个专家库可以容纳多位专家；向 Agent 提交编写请求后，仍需查看预览、
   确认发布并完成正常合入和同步。

随时可以从 `/amux` 重新进入；保存的设置、专家库和引导草稿会保留。
“请求已发送”表示任务已提交，实际结果在当前私聊的任务对话中查看。
专家与 Skill 的关系见[概念说明](../concepts/agents.zh-CN.md)。

## 在能力广场选择一个用法

1. 在负责人私聊发送 `/amux`，点击“能力广场”。
2. 按分类浏览；每页最多 5 项，也可以用“换一个能力”随机查看。
3. 打开“查看使用示例”，阅读能力说明与使用条件；有管理入口的能力可打开对应设置页。
4. 选择“使用示例 1”或“使用示例 2”，将方括号中的链接、名称等替换为自己的信息。
5. 确认后点击“发送给助手”，在当前私聊查看回复并处理按需授权。

浏览、切换示例、修改草稿和打开设置入口都不会自行执行示例。
提交仍经过普通会话路由和权限检查，重复点击同一次提交不会重复执行。
各子页都能返回父页或管理概览；这一流程不会覆盖首次引导进度。
示例是自然语言请求，执行效果取决于当前 Agent、工具与授权，卡片本身不安装 Skill、
不连接外部账号，也不保证当前引擎支持每一项能力。


助手会收到所选能力的前置条件与少量 Hub 状态；已保存设置和运行中状态分开，
尚未检查的健康、可用模型和授权状态保持未知。若引擎未向模型展示已注册的工具，
`amux mcp call <tool> --describe` 可查看真实 Schema，
`amux mcp call <tool>` 从标准输入接收 JSON 参数，沿用相同身份、权限和 Hub。
引擎自带的 Cron 或 Goal 工具不能替代 amux 定时任务或飞书会话目标。
操作成功以真实查询回执及实际结果为准；方括号占位内容需要用户补充。

## 每日推荐怎样工作

- 新配置的机器人默认开启，从次日起每天 11:00 按 **Hub 所在机器的时区**投递；
  在线时约在该时间发送，当天稍晚恢复在线时仍可投递当天卡片。
- 已有安装升级不会自动开启。负责人可在广场开启或关闭，也可以从每日卡片关闭。
  重新开启从次日开始，关闭不影响手动浏览广场或已经创建的任务。
- 每个机器人分别向当前负责人私聊推荐一项能力，不向群发送。推荐在完整目录展示一轮前
  不重复；手动浏览或随机查看不算一次每日投递。
- 偏好和投递记录跨重启保留；每个本地日期最多尝试一次，离线日期不补发，发送失败或
  结果不明时当天不自动重试。没有收到某日卡片时仍可主动打开广场。

每日推荐只介绍用法，不自动创建定时任务或启动其他 Agent 工作。

## 完整能力与示例

以下说明和示例对应卡片中的中英文目录。涉及外部平台的内容依赖已安装的 Skill 与账号权限。

### 自动化与任务

<a id="schedules"></a>

#### 让助手按时做事

用自然语言创建定时任务、查看执行结果和取消任务。创建回执与真实执行结果会分别展示。

**使用条件**：需要在线的 Runtime；外部数据仍需要对应 Skill 和授权。

**示例 1**

> 帮我创建一个在当前对话里每 1 分钟讲一个笑话的定时任务。创建后告诉我任务编号和下次执行时间。收到第一次真实笑话后，我会再说“帮我取消这个定时任务”。

**示例 2**

> 帮我查看当前有哪些定时任务，列出下次执行时间和最近执行结果，先不要修改。

进一步阅读: [定时工作、群值守与文档评论](automation.zh-CN.md).

<a id="calendar"></a>

#### 查看日程与预订会议室

通过正常 Agent 对话查询日历、寻找合适时间，或预订会议室。需要授权时在任务中完成。

**使用条件**：需要日历/会议室 Skill 以及工作账号授权；卡片不代表已经连接日历。

**示例 1**

> 帮我查看这周有哪些会议信息，按日期列出时间、主题和会议地点。

**示例 2**

> 帮我找一个周六晚上 8 点到 8 点 30 分可用的会议室。先确认具体日期、地点和人数，再预订。

进一步阅读: [权限与连接排障](../operations/troubleshooting.zh-CN.md).

<a id="background"></a>

#### 长任务执行时继续协作

实验功能支持前台追问与后台任务展示，也可以为长任务完成设置通知。

**使用条件**：依赖所选引擎能力与相应实验开关；页面会说明即时生效或需要重启。

**示例 1**

> 请说明前台追问、后台任务展示和完成通知各自有什么用，并检查当前开关状态，先不要更改。

**示例 2**

> 我有一个耗时任务 [任务]，想执行期间继续讨论别的问题。先给我适合当前引擎的操作方案。

进一步阅读: [对话、材料与执行结果](feishu-conversations.zh-CN.md).

<a id="goals"></a>

#### 为持续工作设置目标

适合排查测试失败、整理入门指南等需要多轮推进的工作。在工作对话中发送 goal <具体目标> 开始，goal 查看状态，goal pause 暂停，goal resume 继续，goal clear 清除目标并保留对话。命令前不加 /。

**使用条件**：需要当前会话实际支持目标功能；Codex 也要以实际检测为准，Claude SDK 和 Pi 暂不支持。在同一工作对话中控制目标；下方示例只准备目标草稿，不会启动。

**示例 1**

> 我想持续排查某个仓库的测试失败，直到找出有证据的根因并给出修复与验证结果。请帮我拟一条可在飞书工作对话发送的目标消息，格式为 goal <目标正文>，写清范围、允许的操作和完成标准。仓库地址、测试范围或授权不明确时保留占位，并在草稿外告诉我需要补充什么。只准备草稿，不访问文件、不调用工具、不启动目标。

**示例 2**

> 我想把这个知识库整理成带原文链接的新人入门指南：[知识库链接]。请先向我确认阅读范围、目标读者和完成标准，再拟一条可在飞书工作对话直接发送的目标消息，格式为 goal <目标正文>。只准备草稿，不启动目标、不读取知识库、不发布文档。

卡片中的两个示例只帮助拟定目标和完成标准，不启动目标。准备好后，在实际工作的同一对话
中手动发送以下消息；群话题中仍需真正 @助手。当前没有可让 Agent 代管这一功能的
amux MCP 目标工具，不应要求它凭引擎名称猜测支持情况。

| 消息 | 作用 |
| --- | --- |
| `goal <目标正文>` | 创建并开始持续推进；先明确范围、允许操作和完成标准 |
| `goal` | 读取当前目标的真实状态、用量及已有预算 |
| `goal pause` | 暂停目标的自动推进 |
| `goal resume` | 恢复暂停的目标，保留已有用量记录 |
| `goal budget <正整数>` | 显式设置 token 预算；不填写时不自行编造预算 |
| `goal clear` | 清除当前目标，保留对话历史；已发生的外部操作不会撤销 |
| `goal set <新目标>` | 明确替换现有目标；未完成目标不会被普通创建消息悄悄替换 |

这些命令没有 `/` 前缀。话题模式控制该话题绑定的会话，连续对话模式控制共享会话；
去别处查询不会把目标输出搬过去。创建或替换只接收纯文本，附件另发跟进消息。
不支持、受阻或达到预算的状态需按真实回执处理，不能把“恢复”当成解除所有限制。

进一步阅读: [飞书命令参考](../reference/feishu-commands.zh-CN.md).

### 群聊与协作

<a id="group_agent"></a>

#### 每个群用自己的专家与模型

群独立设置可以为不同群选择专家、Runtime、模型、思考强度与对话方式。新的设置用于新会话。

**使用条件**：先在实验功能启用群独立设置并按提示生效，再到目标群 @助手发送 /amux。现有会话保留原配置。

**示例 1**

> 我想给研发群配置代码审查专家、给办公群配置日程专家。先列出可用专家并说明群独立设置步骤，不要修改其他群。

**示例 2**

> 帮我说明如何为一个群设置独立模型和思考强度，以及如何让新会话采用这些设置。

进一步阅读: [群设置与访问控制](feishu-groups.zh-CN.md).

<a id="group_watch"></a>

#### 让助手关注指定群的工作

群值守可以关注选定群的消息并按规则处理工作，管理页可以暂停、恢复和选择执行专家。

**使用条件**：目标群需要使用话题模式，机器人已加入并具备读取消息权限；先显式配置值守范围。

**示例 1**

> 帮我说明群值守如何选择群、设置执行专家和暂停，先不要扩大当前值守范围。

**示例 2**

> 我想让助手值守 [群名]，由擅长 [工作领域] 的专家处理符合条件的新话题。先检查条件并给出设置方案，等我确认。

进一步阅读: [定时工作、群值守与文档评论](automation.zh-CN.md).

<a id="document_comments"></a>

#### 在文档评论里发起工作

负责人在文档评论中 @助手提出请求，由选定专家处理，并在评论里回复。管理页可选择专家与执行选项。

**使用条件**：需要启用文档评论入口、文档权限和事件订阅；普通评论不会自动等同执行授权。

**示例 1**

> 帮我介绍如何在文档评论里向助手提需求，需要哪些权限，以及如何选择处理评论的专家。

**示例 2**

> 我想在文档评论中让助手帮我修改 [工作内容]。先检查文档评论配置并说明触发方式，不要发布修改。

进一步阅读: [定时工作、群值守与文档评论](automation.zh-CN.md).

<a id="context"></a>

#### 让对话按话题组织

连续对话方便接着聊，按话题处理把不同工作的聊天记录分开。话题分开与文件执行隔离是不同设置。

**使用条件**：切换模式走受管确认流程；聊天记录分开不保证文件工作区隔离。

**示例 1**

> 请介绍连续对话和按话题处理分别适合什么场景，并说明它们与文件隔离的区别，先不要修改。

**示例 2**

> 我同时处理 [工作一] 和 [工作二]，请建议怎样组织话题，避免把两项工作的对话上下文混在一起。

进一步阅读: [对话、材料与执行结果](feishu-conversations.zh-CN.md).

<a id="bot_collaboration"></a>

#### 让多个助手协作

Bot 协作可以让受支持的助手相互委派和响应，相关设置由负责人管理。

**使用条件**：需要启用助手协作、可发现的目标 Bot 和允许的执行权限。

**示例 1**

> 请介绍助手之间如何协作，说明当前协作开关状态，以及怎样在目标群查看可协作的助手，先不要发送消息或委派任务。

**示例 2**

> 我想让 [目标助手] 协助 [工作]。先检查可用性与授权范围，给出协作方案后等我确认。

进一步阅读: [任务委派与协作](delegation.zh-CN.md).

### 专家与 Skill

<a id="experts"></a>

#### 给不同工作选择专家

专家像掌握特定 Skill 的人，包含职责和可复用的工作方法。在助手设置中切换日常专家，已有任务保留原快照。

**使用条件**：专家需要已加入当前专家库；切换前查看职责与执行设置。

**示例 1**

> 看看目前有哪些专家配置，按职责和 Skill 列出来，并推荐谁适合做 [工作内容]。

**示例 2**

> 我想切换日常专家。请先列出当前专家、可选专家和切换影响，等我选择后再操作。

进一步阅读: [专家与 Agent](../concepts/agents.zh-CN.md).

<a id="libraries"></a>

#### 一个专家库存放多位专家

用远程 Git 仓库管理多个专家和共用 Skill。添加、同步和管理库复用正式的 Agent Pack 流程。

**使用条件**：需要可访问的 Git 地址；专家配置遵循 Agent Pack 格式，正式采用取决于合入与同步。

**示例 1**

> 帮我检查这个 Git 专家库里有哪些专家、各自有什么 Skill，先只读预览：[Git 地址]。

**示例 2**

> 我想在现有专家库里增加第二位专家 [名字]，负责 [职责]。先检查原仓库并展示变更预览，保留已有专家和 Skill：[Git 地址]。

进一步阅读: [专家库格式与资源管理](../reference/agent-profile-format.zh-CN.md).

<a id="skills"></a>

#### 让专家学会或更新一种 Skill

Skill 是可复用的工作方法，可以带说明、脚本和参考资料。为专家导入或编写 Skill，并检查更新影响。

**使用条件**：需要可读取的 Skill 来源和目标专家库权限；导入完整包，固定版本，确认后发布。

**示例 1**

> 我想让 [专家名字] 学会 [能力]。先检查已有 Skill，给出可导入或自建的方案和来源，确认后再准备专家库变更。

**示例 2**

> 帮我检查 [Git 地址] 中 [Skill 名字] 的更新方案，列出受影响的全部专家，先展示变更预览。

进一步阅读: [专家库格式与资源管理](../reference/agent-profile-format.zh-CN.md).

<a id="delegation"></a>

#### 把工作拆给不同专家

通过任务与专家协作把一项工作分解，让合适的专家各自处理，再汇总结果。

**使用条件**：需要可用专家、Runtime 和执行权限；先确认范围和交付要求。

**示例 1**

> 把 [任务描述] 拆成几项可独立完成的工作，推荐相应专家，先给分工方案，确认后再执行并汇总结果。

**示例 2**

> 请让适合的专家分别审查这份方案的实现、测试和风险，合并为一份带依据的意见：[方案内容或链接]。

进一步阅读: [任务委派与协作](delegation.zh-CN.md).

### 设置与维护

<a id="experiments"></a>

#### 发现实验室里的开关

实验功能包括群独立设置、Agent 记忆、长任务完成通知、前台追问和后台任务展示。管理页区分保存值与当前生效值。

**使用条件**：仅负责人可以更改；按页面提示保存或确认重启。

**示例 1**

> 帮我介绍当前 amux 实验功能分别解决什么问题，哪些已生效、哪些需要重启，先不要修改配置。

**示例 2**

> 我想让长任务完成后通知我。先说明通知阈值和影响，再告诉我如何在实验功能页开启。

进一步阅读: [群设置与访问控制](feishu-groups.zh-CN.md).

<a id="runtimes"></a>

#### 选择工作在哪里、用什么模型执行

Runtime 提供实际执行环境，模型和思考强度决定新任务的执行组合。助手设置展示当前真实选择。

**使用条件**：需要可用 Runtime 和模型；更改默认值不会把运行中任务迁移到另一个环境。

**示例 1**

> 请说明执行机器、运行引擎、模型和思考强度各自控制什么，结合当前助手默认设置，告诉我在哪里查看和选择真实可用项，先不要更改。

**示例 2**

> 针对 [工作内容] 推荐一个可用的模型和思考强度，说明质量与耗时的取舍，等我确认后再调整。

进一步阅读: [Runtime 与执行位置](remote-runtime.zh-CN.md).

<a id="maintenance"></a>

#### 查看系统状态与安全维护

管理页汇总系统状态和版本，可检查更新或按确认流程重启。

**使用条件**：仅负责人可执行维护；更新与重启使用管理页确认流程。

**示例 1**

> 请帮我解读当前 amux 版本和连接状态，区分已知状态与尚未检查的项目，并告诉我怎样在管理页查看系统状态，先不要重启或更新。

**示例 2**

> 我想了解升级 amux 的流程和对运行中工作的影响。请说明怎样在管理页检查更新、核对目标版本并确认升级，先不要安装或重启。

进一步阅读: [系统维护](../operations/maintenance.zh-CN.md).

## 怎样确认体验成功

- **定时任务**：保留真实任务编号和下次执行时间，等到当前对话收到第一条真实笑话，
  再发送“帮我取消这个定时任务”，核对同一规则已停用。创建回执不等于已经运行。
- **设置与专家**：保存后核对摘要，用新会话验证实际专家、模型和思考强度；已有任务保留原配置。
  添加或更新专家库还要确认正式版本已合入并同步，Agent 的草稿不等于已安装版本。
- **目标与委派**：检查目标状态卡或实际任务/实例编号，区分目标草稿、请求已接受和工作已完成。

## 无法继续时

| 现象 | 下一步 |
| --- | --- |
| 广场要求私聊或无权操作 | 使用该机器人的负责人账号，在机器人私聊重新发送 `/amux` |
| 卡片提示能力已调整或无法保存 | 返回广场重新选择，暂时失败时稍后重试 |
| 请求是否发送成功不明确 | 先查看当前私聊任务回复；同一提交不自动重发，确认未执行后再决定是否重试 |
| 外部链接读不到、日历不可用 | 检查对应 Skill、资源访问范围与授权，按 Agent 提示完成账号授权 |
| 更换模型或专家后没有变化 | 核对新会话默认值与当前会话实际值，在新会话验证 |
| 目标功能不支持 | 以真实会话检测结果为准，选择支持的引擎，或按普通任务执行 |
| 没有收到每日推荐 | 检查开关、开启日期、Hub 时区与当天在线情况；当天发送失败不自动重试 |
