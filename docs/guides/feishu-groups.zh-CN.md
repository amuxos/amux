# 群设置、访问控制与批准

[English](feishu-groups.md) | [简体中文](feishu-groups.zh-CN.md)

本指南面向机器人负责人：把助手交给同事使用，为不同群选择专家与对话方式，并明确谁
可以控制执行。普通成员只需要按群策略 @机器人；管理卡不会把成员自动提升为负责人。

## 先区分三种设置

| 设置 | 解决的问题 | 不能由它推断什么 |
| --- | --- | --- |
| 负责人模式 / 协作模式（`owner_only` / `shared`） | 谁可以在本群发起工作 | 不代表能重启系统、批准所有请求或读取所有凭据 |
| 连续对话 / 每个话题独立（`singleton` / `thread`） | 新消息进入哪段 Session | 不代表文件系统、用户身份或记忆已经隔离 |
| 话题用户隔离 | 是否强制按已配置的 Linux UID/DAC 边界执行 | 需要主机、身份和授权准备，不能只靠选择一个 UI 选项完成 |

例如，研发群可以允许多人协作，但让每个话题独立；项目群可以使用本群的一段连续对话。
这两种情况下，系统升级和重启仍由负责人或运维者管理。

## 让同事参与

1. 确认机器人已加入目标群，且你是 amux 配置的机器人负责人。
2. 在群里真正 @机器人并发送 `开启协作模式`。这是确定性识别的命令短语，不是让 Agent
   自行猜测怎么修改设置。
3. 再 @机器人发送 `/amux`，核对当前群的访问模式。
4. 请一位同事在新话题中 @机器人提出小请求，验证访问和执行环境均可用。
5. 需要收回群协作时，由负责人发送 `关闭协作模式`，再查看状态确认。

协作权限只处理本群准入。安装启用了执行身份管理时，成员还可能需要相应身份或服务
成员资格；“已开启协作”不保证所有后续授权都会通过。普通成员也不能仅凭群成员身份
中断别人创建的话题、改变其绑定或批准别人的执行请求。

## 打开本群管理入口

负责人在目标群的根消息里 @机器人发送 `/amux`：群里显示可共享的状态摘要，机器人还会
向负责人私聊发送与该群绑定的管理卡。到私聊核对群名称、群 ID 和当前助手，避免修改错群。
在已绑定话题里发送 `/amux` 查看的是当前工作；要查看群设置应回到群级入口。

没有启用独立群配置时，群仍沿用原来的机器人设置，管理入口主要展示权限和值守信息。
仅打开一张卡片不会创建 Session，也不会让这个群自动进入独立配置模式。

## 为一个群设置独立默认值

### 启用实验

群独立配置默认关闭。负责人在私聊 `/amux` → 实验功能中启用“群独立配置”，保存后
确认重启系统。保存配置与让运行中的系统使用它是两步；重启可能影响正在执行的工作，
应先检查当前状态。

该开关允许使用群配置功能，并不会一次性迁移所有群。每个群只有在首次保存自己的完整
设置后才启用独立策略。未保存的群和私聊继续使用原来的机器人行为。

### 保存与核验

1. 在目标群 @机器人发送 `/amux`，打开私聊收到的“当前群设置”。
2. 选择“修改本群设置”，检查对话模式、访问范围、默认专家和执行选项。
3. 根据页面提供的字段编辑；较多字段可能分页显示。未保存的选择只是草稿。
4. 保存后返回摘要，核对“设置来源”和“新会话默认专家”等信息。
5. 发起一个新话题，或在需要时新开本群连续会话，核对实际专家与模型。

保存会校验整个设置，不会只接受其中有效的一半。卡片携带版本信息；如果配置已被另一
次操作更新，旧卡片会报过期或冲突。重新在目标群打开 `/amux`，查看新值后再修改。

### 各字段如何理解

| 字段 | 当前作用与约束 |
| --- | --- |
| 群对话方式 | 本群连续会话、每个话题独立，或话题独立并启用用户隔离 |
| 新会话默认专家 | 选择已安装的 Profile；“跟随助手默认专家”只继承专家选择，不会退出独立群策略 |
| 运行引擎 | 选择当前安装支持的引擎，或使用所选专家的原生引擎；不等于选择执行机器 |
| 模型、思考强度 | 必须满足 Profile、引擎和模型的约束；保存并不会为模型购买服务或授予凭据 |
| 执行过程展示 | 控制过程面板折叠、展开或隐藏；不改变执行权限 |
| 谁能发起工作 | 仅负责人，或允许群成员，仍受机器人与执行身份检查 |
| 目标机器 | 选择 Runtime 执行位置；填写的目标必须能够唯一解析 |
| 工作目录 | 使用目标机器上的绝对路径；本机路径不会自动复制到远端 |
| 附加参数 | JSON 字符串数组，例如 `["--flag", "value"]`；实际参数必须是该引擎支持的值 |
| 空闲超时 | 以秒为单位，0 禁用自动睡眠，其他值至少 60；睡眠不等于删除聊天与工作区 |
| 上下文消息数 | 控制后续输入选择的共享话题记录，同时仍受上下文预算限制 |
| 群会话数 / 每用户会话数 | 限制新建会话容量，0 表示不限；不是 token 配额 |

空的运行引擎、模型和思考强度使用所选 Profile 的默认值，不表示持续跟随机器人的全部
执行设置。修改默认值主要作用于新创建的 Session；已有话题、显式 `/run` 选择和
`/bind` 接入的 Session 保留自身的执行身份及配置。

## 从共享机器人上下文切换为群自己的对话

机器人级 singleton 可能覆盖私聊及多个群。为某群保存独立连续会话策略后，该群后续
工作使用自己的 Session，其他群和私聊不被迁移。系统不会把机器人的全局对话历史或
凭据复制过来，首次有效输入才按新策略开始工作。

本群管理卡分别显示“新会话默认专家”和“当前会话专家 / 模型”。两者不同可能只是
默认值已改，而旧连续会话尚未替换。

需要空白上下文时，负责人选择“新开连续会话”：旧的默认输入指针被退役，已接受的
工作继续完成；下一条有效的新输入建立本群新会话。回复旧连续会话的消息不会继续驱动
旧执行，也不会被改投新会话。普通独立话题的已有绑定仍按其生命周期工作。

开启群值守的群必须先关闭本群值守，才能切换到本群连续会话。值守需要独立话题，详见
[定时工作与群值守](automation.zh-CN.md)。

## 选择隔离边界

“话题独立并启用用户隔离”是在 `thread` 路由上增加强制隔离要求，不是第三种路由枚举。
运维者需要先准备 [Linux 隔离后端](../operations/linux-dac-isolation.zh-CN.md)、用户身份
和工作区访问条件。环境不支持、身份缺失或显式绑定的 Session 不兼容时会失败，不会
自动换成较弱隔离继续运行。

主机启用隔离能力，也不表示所有普通飞书会话会自动切换到隔离模式。已启动的 Session
保留创建时的执行环境；改变群设置不是迁移已有进程的方法。

安装启用了 Principal 隔离策略时，机器人及群连续会话需要对应机器人的服务身份和
发送者的有效服务成员资格。个人话题的身份登记、群协作开关都不能替代这一条件。
由运维者完成配置，不要把身份失败当成“需要再开一次协作模式”。

## 处理执行权限请求

一次执行还可能发起文件、命令、工具或问题请求，与群准入分开处理。

1. 查看卡片所属会话和具体操作，确认路径、目标及选项含义。
2. 由具备响应权限的负责人或请求关联用户作答；需要多选时按卡片提交完整选择。
3. 等待卡片显示已处理，再核对执行是否继续。
4. 若显示“已处理或已过期”，查看最新状态；若提示回传失败，先检查连接，不把成功点击
   当成执行已获授权。

拒绝某次请求、停止 Session、取消子 Task 是不同操作。Task 的 `policy-allow`、
`deny-all`、`escalate-to-main` 决定其权限请求如何处理，不创建文件系统边界，也不提供
缺失的凭据。详见[任务委派](delegation.zh-CN.md)。

## 关闭实验或处理异常

关闭“群独立配置”并重启后，已经保存独立配置的群会暂停接收新输入及自动工作，保留
设置、绑定和已接受工作的输出。它们不会自动回退到机器人的全局连续会话。重新启用并
重启后才恢复原策略；未独立配置的群和私聊继续沿用原有行为。

| 现象 | 处理方法 |
| --- | --- |
| 群里只有摘要，没有编辑字段 | 负责人查看私聊管理卡，确认实验已启用且系统已重启 |
| 已打开设置，但群行为没有变化 | 检查是否实际保存，设置来源是否仍显示沿用助手 |
| 模型或专家仍是旧值 | 比较新会话默认值与当前 Session，使用新话题或新连续会话验证 |
| 保存报配置已变化 | 重新打开当前群卡片，基于最新值修改 |
| 切换连续会话被拒绝 | 检查本群值守是否仍开启 |
| 协作成员仍不能工作 | 查看机器人准入、执行身份、服务成员资格、隔离与容量限制 |
| 关闭实验后群暂停 | 按提示恢复实验并重启；暂停是保留隔离与路由边界的预期行为 |

正式契约见 [Bridge 模型](../current/feishu-bridge-product-model.zh-CN.md)和
[Session 模型](../current/session-product-model.zh-CN.md)。
