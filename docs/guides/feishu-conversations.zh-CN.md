# 在飞书中与助手协作

[English](feishu-conversations.md) | [简体中文](feishu-conversations.zh-CN.md)

本指南从第一次发需求开始，说明如何补充材料、继续追问、查看执行进度，以及中断或重新
开始对话。你需要一个已接入的机器人和使用权限；接入负责人可先阅读
[机器人接入教程](../tutorials/first-feishu-bot.zh-CN.md)。

## 开始前确认当前场景

同一个 `/amux` 在不同位置提供不同入口。在群中通过飞书选择器真正 @机器人，再发送命令；
手工输入的 `@名称` 可能只是普通文本，不会被平台识别为提及。

| 发送位置 | `/amux` 提供什么 | 接下来怎么做 |
| --- | --- | --- |
| 与机器人的私聊 | 助手状态、设置与系统维护入口，操作受身份限制 | 查看当前专家和消息处理方式，负责人可管理设置 |
| 群里的新根消息 | 当前群的权限、消息处理方式与值守状态 | 确认自己能使用机器人；负责人同时检查私聊里的本群管理卡 |
| 尚未绑定的新话题 | 开始工作的说明 | @机器人描述需求，或使用可用的 `/run`、`/bind` |
| 已绑定的活跃话题 | 当前会话的工作状态与操作 | 在该话题内继续补充、查看状态或中断 |

`/help` 展示当前场景的命令。按钮或命令存在，不代表当前 Agent 支持它，也不代表每个
查看者都有执行权限。普通用户不需要在终端运行 CLI。

## 开始工作并继续补充

以下流程以群里的独立话题模式为例。持续对话模式的复用范围见下一节。

1. 在群里 @机器人，说明目标、材料、期望产物和允许的操作。
2. 等待回复卡片出现，核对它正在处理的内容；需要授权时先处理对应请求。
3. 在原话题中 @机器人继续追问，保持需求和结果在同一处。
4. 最后核对实际产物和完成状态。需要独立上下文的另一件事，另发一条根消息。

例如，先发送：

> @助手 请审阅这份方案，找出三个实现风险，引用对应段落。在这里回复意见，先不要修改文档。

收到结果后，在同一话题中追问：

> @助手 请把第二个风险展开为复现条件、受影响范围和两个修复方案，沿用刚才的材料。

在协作话题中，成员间未 @机器人的普通讨论会被记录为有限上下文，不会单独触发回答。
要让助手根据讨论继续工作，应明确 @它；不要把“不回复每条群消息”误认为断线。

### 回答中途补充，会发生什么

你在自己请求的执行过程中发送的纯文本追问，默认会被**注入当前执行**（steer），而不是
中断它：连续输入先在约 2 秒的窗口内合并，然后作为“用户在执行过程中追加的消息”交给
正在工作的 Agent。Agent 自行判断这是对当前工作的纠正，还是追加的新任务，并保留已完成
的进度。Claude 会在当前工具调用结束后的边界读到它；纯文本回答中途的追问会在这段回答
结束后立即处理，仍算同一次执行。Codex 通过原生 `turn/steer` 注入。

只有发起当前请求的人可以注入。群里其他成员的消息、group-watch 告警和其他 Bot 的消息
会排队，在当前执行结束后作为下一次执行运行，不打扰当前执行。当前执行无法接收注入时
（执行刚好结束、正在被中断、已有更早的消息在排队、Agent 不支持，或者发送者权限与当前
执行不一致），追问同样会排队。带图片或附件的输入走材料处理路径，不能依赖同样的文本
合并窗口。

如果 amux 无法确认当前执行是否收到了追问（例如超时），它不会再排队一份，因为这条追问
可能已经在执行。请先查看回复，确认没有被处理再重发。

需要立刻停止时，发送 `中断` / `/interrupt`；话题模式下可发送 `停止` / `/stop` 结束任务。
中断也会取消已经注入这次执行的追问，仍需要的话请重新发送。已经执行过的文件修改、
外部工具操作不会因中断自动撤销。运维可以设置环境变量
`AMUX_FEISHU_BUSY_INPUT=interrupt` 恢复旧的“追问即中断”行为。

在单例（singleton）会话中，前台会话负责对话与调度：耗时较长的工作会被委派给后台
Agent Instance。对后台任务的纠正由前台 Agent 用 `amux.instance_steer` 转达给对应实例。

## 明确消息会进入哪段对话

| 消息处理方式 | 复用范围 | 如何开始独立上下文 |
| --- | --- | --- |
| 机器人连续对话（`singleton`） | 该机器人绑定的一段 Session，可覆盖获准的私聊和多个群 | 负责人使用私聊 `/amux` 的对话管理入口 |
| 每个话题独立（`thread`） | 同一活跃话题继续自己的 Session | 新建一条根消息；在旧话题追问会继续旧会话 |
| 独立群的连续对话 | 该机器人在该群的一段 Session，不与其他群、私聊共用 | 负责人在本群设置选择“新开连续会话” |
| 话题独立并启用用户隔离 | 独立话题加上部署已具备的 Linux 用户隔离 | 新开话题；执行身份与访问条件仍需通过检查 |

同一个专家名称不等于同一段会话。话题分开也不等于文件系统隔离：它可能仍使用同一
执行机器和已配置的工作区。把机器人加入多个群前，应确认连续对话是否会共享上下文，
需要按群独立时由负责人配置[群设置](feishu-groups.zh-CN.md)。

独立群的连续对话直接在群里展示输出。旧连续对话被退役后，回复它的旧来源会得到重新
开始的提示，不会悄悄改投新对话；已接受的工作仍可完成。

## 提供材料与引用

可以发送文字、图片、文件及合并转发消息，并说明要从中提取什么。引用回复可用于指定
“这条消息”；共享话题上下文只会选择有限的相关记录，不等于机器人能读取全部群历史。

- 文件读取使用机器人应用的访问权限；用户自己能打开，不等于机器人也能读取。
- 图片能否被理解还取决于当前 Session 和 Agent 的能力。资源读取失败、超过限制或能力
  不支持时，应查看材料提示，改用较小文件、文字摘录或让负责人检查权限。
- 合并转发只展开平台返回的后代消息，不能借此任意抓取其他聊天的附件。
- 修改已经发出的消息不会自动重新提交给 Agent。重要更正应作为新回复发送并 @机器人。

返回文件与输入附件使用不同限制。当前 Agent 产物每轮最多上传 10 个文件，每个不超过
30 MB，总计不超过 300 MB；可识别图片在 10 MB 内使用图片展示，较大的图片在允许范围
内作为文件发送。Agent 说“已生成文件”与文件实际上传成功是两件事，应检查返回附件。

## 看进度并处理请求

主回答卡片会更新过程与结果。展开执行摘要可查看专家、模型、耗时，以及 Provider 提供
的用量信息；未提供的数据不会由 amux 编造。累计 token 可能包含该原生对话之前的轮次，
不能当作这次请求的独立账单，也不是主工作与所有子工作的总和。

如果 Agent 通过 amux 委派工作，会出现独立的子任务进度卡。主卡与子卡分别记录各自
执行；子卡完成后，主 Agent 可能仍在汇总。具体读法见[任务委派](delegation.zh-CN.md)。

遇到权限或问题卡片时：

1. 查看请求所属的会话、待执行的操作或问题，不要只看“允许”按钮。
2. 按卡片提供的选项回答；选择会发送给那一次请求。
3. 确认卡片显示已处理，再观察当前执行是否继续。失效、重复点击或身份不符会被拒绝。

负责人和请求关联的用户按权限检查处理请求，不是所有群成员都能批准。某些工具操作已被
策略允许，不会再弹卡；`/amux` 的群权限也不等于文件或工具权限，详见
[访问控制与批准](feishu-groups.zh-CN.md)。

## 中断、开始新上下文或结束

| 操作 | 当前实现的效果 | 需要注意 |
| --- | --- | --- |
| `/status` | 查看当前绑定的 Session 状态 | 不是另一条分析请求 |
| `/interrupt` | 请求中断当前 Agent 执行，保留会话 | 已完成的外部操作不会回滚，也不等于取消所有子 Task |
| `/restart` | 重启当前 Session，按 Agent 能力恢复已有历史 | 不是重启整个 amux 系统，也不是清空上下文 |
| `/compact` | 排队压缩上下文，保留关键摘要 | 当前仅支持 Codex 兼容 Session；前序输入完成后才执行 |
| `/clear` | 排队切换到新的原生对话上下文，保留 Session 绑定 | 同样依赖 Codex 兼容能力；不删除工作区文件或 Hub 记忆 |
| `/stop` | 结束当前话题 Session 和绑定 | 机器人级 singleton 会拒绝这种话题生命周期操作并引导到管理入口 |

因此，想“暂停回答”应使用中断；想“忘掉本轮上下文”使用支持的清理或新开对话；想删除
跨会话记忆，需要单独执行[记忆更正或遗忘](memory.zh-CN.md)。

### 使用已经加载的 Skill

当前 `/skill` 选择器适用于 Codex 兼容 Session。先让会话建立，再发送 `/skill` 查看它
实际加载的技能，选择技能并填写具体任务。也支持 `/skill <name> <task>`，其中名称必须
来自当前会话的可用列表。它不会安装一个不存在的 Skill，也不因名称相同而切换专家。

## 一次完整对话的自查

完成一次试用时，应能确认：请求在预期话题或群内得到回应；追问引用了正确材料；需要的
授权已处理；完成的是可检查的结果或附件。若更换默认专家后旧会话仍显示原专家，这是
预期行为——默认值作用于新启动的 Session。

| 现象 | 先检查什么 |
| --- | --- |
| 群里没有回答 | 是否真正 @机器人、是否有使用权限、是否只是未提及机器人的协作讨论 |
| 旧话题提示重新开始 | 话题是否已结束，或原群连续会话是否已退役 |
| 回答被打断或多条补充一起处理 | 是否在执行中连续发送了纯文本修正 |
| 看不见引用或附件 | 机器人访问权限、材料提示、Agent 能力和材料大小 |
| `/clear` 或 `/skill` 不可用 | 当前 Agent 是否兼容，是否已有有效绑定 |
| 一直等待授权 | 是否有未处理卡片；文档评论触发的请求还要检查机器人私聊 |

进一步排查见[排障指南](../operations/troubleshooting.zh-CN.md)。行为定义与完整命令见
[Session 模型](../current/session-product-model.zh-CN.md)、
[Bridge 模型](../current/feishu-bridge-product-model.zh-CN.md)和
[飞书命令参考](../reference/feishu-commands.zh-CN.md)。
