# 飞书 Bridge 产品模型

[English](feishu-bridge-product-model.md) | [简体中文](feishu-bridge-product-model.zh-CN.md)

## 产品入口与对话契约

飞书是产品面向用户的主要交互入口，包含私聊请求、群提及、话题追问、管理卡片与权限
响应。CLI 和 MCP 继续提供控制及集成入口，普通飞书用户不需要先掌握终端操作。

一条飞书消息可能打开管理、触发控制操作、记录成员讨论，或排队提交 Agent Turn，
并不总是创建 TaskRun。机器人级 singleton、话题绑定和实验性的群 singleton 具有
不同复用范围。[Session 模型](session-product-model.zh-CN.md)定义身份与边界，
[Task 模型](../distributed-task-model.zh-CN.md)定义委派与持久实例。

群协作访问、消息处理方式（`thread|singleton`）和强制 Linux 用户隔离是独立设置。
协作话题内未提及机器人的成员讨论可成为有限上下文，但不启动新的回答。显式命令仍受
场景、Agent 能力和绑定控制权限检查约束。

[飞书命令参考](../reference/feishu-commands.zh-CN.md)从命令和帮助注册表及双语管理词表
生成。展示命令不等于授予执行权限。自然语言委派或定时请求需要 Agent 工具，并应以
真实记录核实；话题不支持 `/schedule` 和 `/sched`。

## Bridge 职责

可选 Bridge 拥有飞书/Lark API 行为、消息路由、Bot 命令、thread 与 workspace 绑定、
权限和输出呈现。它不拥有智能体执行，也不改变本地 CLI 的要求。

群值守与文档评论的执行覆盖遵循所选 Runtime 的模型策略。没有 Runtime 覆盖时，
遵循 Profile 模型策略：省略 `supported_models` 允许原生模型名；显式列表将选项限制
在列表内；显式空列表仅允许 Agent 默认模型。CLI 校验与 Bridge admission 使用同一规则。

Operator 通过官方应用注册流程配置 Bot Profile。Setup 申请已实现能力所需的权限和
事件。Personal 与 Team 治理独立于系统托管拓扑控制访问。Owner 操作与普通对话动作区分。

仅 Owner 可操作的「实验功能」页提供长会话完成通知、群独立配置与 Agent 记忆
三个独立开关，默认均关闭。
Agent 记忆使用安装级 `memory.enabled` 配置，无需 Agent Profile。
非用户隔离模式下记忆跨 Runtime 全局共享，用户隔离模式下按有效 Principal 分开。
页面展示已保存值，并为与当前运行值不同的实验逐项标记待重启。
保存前校验整个表单，在一次原子写入中更新已提交的实验并保留无关配置；旧卡片
缺少记忆或群独立配置字段时，在同一文件锁内保留其最新已保存值。保存不会改变
运行行为，Owner 需单独确认系统重启，取消重启仍保留设置。开启并重启后，
新对话可使用记忆，旧的非受管对话不会自动接入。关闭会保留记忆文件，也不能清除已进入对话上下文的内容。
卡片标题不增加单独的记忆用量计数。

接受的消息映射到工作区和 Session。Session 输入进入队列；thread 上下文有界，并附在
已接受的提交上。智能体进度、工具活动、结果与权限提示均从结构化事件渲染。
Bridge 不从展示文本推断 Provider 语义。

每个绑定的 Session launch 只有一条活动输出流。并发绑定、输入路由和 Session-added
通知复用该流及其 readiness、turn 状态和卡片句柄。重复启动通知不能冻结已有进度卡，
也不能把同一 turn 的结果放到新卡片。Session 或 launch 身份变化、binding 迁移以及
流已结束时仍会建立新 attachment。新建 Session 可从首次 Hub 快照补齐身份而不替换活动流。

Agent 回复卡片将状态、专家/模型、耗时与用量集中在可折叠的执行摘要中，不增加独立
标题栏；流式输出、完成和紧凑降级均沿用这一布局。模型使用可读的目录名称，
不展示编码后的服务引用。
主卡与子卡标题使用相同的结构化用量摘要。已知上下文窗口时，最新调用总量显示为
`22.8k tokens (8%)`，否则省略百分比。报告缓存输入时，Provider thread 的原生累计
输入显示为 `累计输入 300k/343k（缓存/总量）`；没有缓存输入值时显示 `累计输入 343k`。
累计输出显示为 `累计输出 12k`，两者单位均为 token。显式零值保留，缺失的累计字段省略，
不从最新调用推断，也不累加更新。上下文占用继续使用最新调用，与累计消耗独立。
可选的首 token 延迟和 token 速度仍包含在摘要中。CardKit 与旧版卡片共用这些规则；
用量更新不会让每个事件帧都触发卡片刷新。

群值守接受允许的根消息，内容可以是文本、有效图片、文件或合并转发。
纯素材消息使用共享解析器的描述作为 Session 输入。已删除消息及无有效文本或素材的
消息不创建 Session。既有发送者、群、去重、容量和防循环规则继续适用。

群值守的 `sender_types` 是有效配置中各值守群的默认发送者白名单。
`chat_sender_types.<chat_id>` 可为单个值守群覆盖该白名单，使同一个 Bot Profile
可以在一个群只接收 App 告警，在另一个群只接收用户消息。覆盖项不会自动把群加入
值守；对应群仍必须出现在 `chat_ids` 中。未配置覆盖的群继续使用 `sender_types`。

可选的报警去重只作用于 App 发送的群值守根消息，默认关闭。Bridge 根据发送 App 和
规范化后的卡片可见文本生成稳定指纹，优先采用 Rule ID 与卡片标题；窗口从确认创建
Session 开始计算，被抑制的消息不会延长窗口。原子持久化预占阻止不同根消息并发创建；
容量或策略拒绝会释放预占，Run 失败后只有 Runtime 确认该名称的 Session 不存在才释放。
Runtime 不可用时保留待确认状态；至少一分钟后，后续同类报警先查询 Runtime 再决定是否
重试。只有 running、idle、sleeping 状态证明启动完成，created 仍保留待确认。
找回的 Session 若已有持久化输入回执则抑制重复；否则复用原话题和 Session 提交新的同类
报警，不再创建 Session。输入提交成功后才确认去重窗口，起点为已确认的创建时间
（恢复时使用恢复确认时间）。Submit 发出前先持久化派发标记；如果响应或本地回执丢失，
从派发时起抑制同类报警一个配置窗口，不自动重放结果未知的提交。窗口结束后新的报警
可正常启动。尚未派发输入且已 archived/failed 的 Session 会释放预占，不会永久阻塞。
用户消息和不同群互不影响，
message_id 去重仍先于报警语义去重执行。实时 Bot Open ID 与历史 App ID 通过完整群 Bot
目录统一成 App ID；开启此功能需要 `im:chat.members:read` 权限。查询失败、不完整或找不到
发送者时返回错误，不消耗消息 ID。纯图片、文件、音频、视频和转发消息的占位文本不作为指纹。

App 发出的根告警如果只 @ 人，仍可触发群值守。@ 当前智能体继续走普通路由；
@ 其它智能体的 App 消息不自动处理，同时 @ 人和智能体时也不接管。
实时事件与历史轮询遵循相同规则。事件中明确的提及目标类型作为判断依据；
平台未提供类型时（例如历史消息），Bridge 使用当前群的完整机器人名单核对目标 ID。
该查询需要 `im:chat.members:read`，不依赖是否开启智能体协作，每轮轮询每群复用一次查询。
名单查询失败或不完整时，不提交身份未确认的消息并报告错误；这些消息仍可在回看窗口内
由后续轮询处理。不含模糊提及的消息不需要该查询。

普通对话、实时群值守事件和历史轮询通过同一路径收集素材。
每条消息拥有自己的收集上下文，轮询批次中附件不会串到其它消息。
素材获取使用当前 Bridge 应用身份和所属群，各入口共享 Session 能力、大小限制、
文件物化和错误提示。仅展开合并转发容器返回的后代消息。
只有飞书明确报告后代与容器属于同一群，才可使用后代原始消息 ID 获取资源；
否则仍以顶层容器 ID 获取。

Agent 产出的 outbox 成果独立遵循飞书消息上传限制，不与输入素材共用大小限制。单个文件最多
30 MB，每轮最多 10 个文件、合计 300 MB。识别为图片且不超过 10 MB 时使用图片上传接口并保留
图片展示；超过 10 MB、但不超过 30 MB 的图片改用文件上传接口发送。

Bridge 状态按职责分组为 controller、store 和 API port。路由与应用装配仍在 Bridge；
所有权调整保留事件顺序、流生命周期、权限和发行版 hook。

新工作区默认使用 `builtin/codex`。Bot 可以选择可用的 Profile 与 Runtime。
公共品牌指向 amux 官网 `https://amuxos.com/`。委派协议保留稳定标识
`urn:amux:protocol:feishu-external-bot-delegation:v1`，不随官网地址变化。
外部 Bot 发现和新建委派要求与当前群存在活动 binding，不允许跨群发现。
既有委派工作可使用已记录的对端身份完成。

公共发行版不包含旧控制台自动化，也不读取其它工具的网页登录缓存。
Operator 可以使用官方注册流程或手动配置应用。

独立维护的发行版可在 Bridge 首次使用前注册一个扩展，提供 Provider 呈现、协调
Profile 识别、旧默认值的事务性迁移，以及显式控制台 setup 回退。
首次使用后注册不可变，重复注册报错。这些 hook 不改变 Session 执行、canonical
事件、访问校验或默认官方注册流程。发行版特有实现和 Session 缓存路径属于发行版
module；公共 Bridge 无需它们也可独立运行。

Parent 活动卡汇总协作任务，不把其输出混入 parent Agent 的过程面板。
每个新发现的任务在每个 Bridge 进程内创建一张子进度卡，原地更新至终态结果。
标签由短 Profile 名加 Persistent Agent Instance ID 的前八位组成；普通任务使用准确
child Session ID，child 创建前临时回退到 TaskRun ID。Profile 标签去掉命名空间与版本，
缺失时回退到 Agent Type，再回退到 `agent`；身份后缀去掉 `agent-` 或 `task-` 前缀。
卡片显示状态、Profile、耗时和已知的有效模型。身份与模型来自同一 target 上的准确
child Session，不能取自 parent 或输出文本，并在终态清理后继续显示。

子卡只按工具 ID 聚合自身脱敏的结构化工具活动，在独立过程面板显示 TaskEvent 输出。
可附带 child Session 自己的只读查看链接。CardKit 创建失败时回退为一张旧版交互卡，
后续更新继续原地 patch 该卡。

Child 用量仅来自对应 TaskRun 的结构化 `usage` 事件和最终 `TaskResult.usage_json`。
基于 sequence 去重，确保 replay 和终态清理期间保留最新用量。
每张卡展示自身 child Provider thread 的累计快照；persistent child 复用 thread 时，
可能包含较早 TaskRun 的用量，不包含 parent 或其它 child 用量。

Parent turn 期间约每两秒发现一次任务，turn 结束时再做最后一次发现。
每个 watcher 从 sequence 0 重放 TaskEvent，断线后从最后序号继续，不重复事件。
状态、权限和结果立即更新子卡，输出更新按两秒合并。
Watcher 可在 parent turn 结束后继续存在，直至 child Task 终态、超时窗口到期或进程退出。
Parent 摘要保留约三十秒的刷新节奏。

## 对话控制与文档评论

`/compact`、`/clear` 和原生 `/skill` 选择器当前要求 Codex 兼容 Session。
compact/clear 提交排队控制；interrupt 路由到当前 Session，不代表取消全部关联 Task。
[Session 模型](session-product-model.zh-CN.md)定义普通追问的抢占与文本合并。
相关输入路径见 `internal/bridge/` 下的 `router_control.go`、`router_submit.go`、
`coalesce.go` 和 `skill_picker.go`。

文档评论接入单独启用。在读取文档或启动执行前，要求真实提及机器人、已确认负责人
以及负责人访问权限。群协作不会把该能力授予其他成员。绑定按机器人、文档和根评论
区分，同一评论串中的后续提及复用该绑定。接入读取具体请求与可获得的有限文档上下文，
对事件去重并回复评论，本身不修改文档正文。权限卡发送给发起负责人的私聊，并在评论
提示前往处理。读取、启动或提交失败都有显式处理；仅启用设置不证明平台权限或订阅
已经可用。实现见 `internal/bridge/document_comment.go`。

## 群独立配置

群独立配置是实例级实验功能，默认关闭（`bridge.feishu.group_settings.enabled = false`）。
负责人通过私聊 `/amux` → 实验功能开启，选择“保存并重启”。保存只更新配置文件；
运行中的 Hub 保持启动时的开关，重启后生效。关闭时群编辑、旧卡片回调和本机运维
命令不可用。已保存独立设置的群暂停新输入和自动任务，不回退 Bot 默认，也不降低
隔离要求。群配置、Session 关联和已接受任务的输出保留；重新开启并重启后恢复
已保存的策略。未保存独立设置的群和私聊继续沿用既有 Bot 行为。

每个 `(bridge_id, chat_id)` 可独立设置处理方式、Profile、Runtime、模型、思考强度、
过程展示、target、cwd、参数、空闲超时、上下文条数及会话配额。负责人从有效 Bot
和工作区配置创建完整草稿，保存采用原子事务和版本校验。群未保存独立配置时保留
Bot 级行为。群访问模式与话题/连续会话模式、执行隔离分别管理。

新话题使用保存的群执行参数。Runtime 使用 Profile 默认值时也校验并落实显式思考
强度，仍遵循 Profile 的模型/Provider 选择与模型策略。显式 `/run` 选择和绑定 Session
保留自身身份；修改默认值不会改变已有 Session 的 Profile 或执行配置。要求隔离时，
不得静默降级或通过绑定旧执行绕过。

Linux 隔离能力与飞书会话的隔离选择相互独立。新建普通话题和连续会话显式选择
passthrough；隔离话题选择 linux-dac，不可用时拒绝启动。该选择遵循有效群设置，
私聊和未配置群使用 Bot 默认值。启用宿主隔离能力不会自动隔离所有飞书会话。
宿主要求可识别身份时仍保留执行 Principal 和 actor credential；passthrough 只改变
进程隔离方式，不改变执行授权。已有或显式绑定的 Session 保持冻结的执行环境。

群连续会话按 Bot 和群各维护一个 Session。回复、进度、权限请求和产物直接发送到
该群，与 Bot 连续会话的输出方式相同。新输入和显式指向输出消息的回复进入同一
队列。首次输入只作为内部绑定锚点，不作为话题输出目的地。不同群和私聊不共享
Session。改变模式或负责人新开会话会退役旧默认关联，已接受任务继续完成。
回复已退役入口时提示新开话题；普通已有话题关联仍可使用。

启用 Principal 隔离时，群连续会话和 Bot 连续会话都要求 Bot 作用域的
`service:<bot-profile>` alias，以及发起者的有效 service membership。个人话题身份
注册不会自动建立共享执行身份，群的 `shared` 访问模式也不授予 membership。
运维人员应在启用隔离时配置这些前提，见
[Linux 隔离指南](../operations/linux-dac-isolation.zh-CN.md#飞书连续会话的共享身份)。

群值守的资格和继承执行参数遵循目标群策略；显式能力执行覆盖仍须满足群隔离要求。
完整设计及状态转换见[实现规格](../superpowers/specs/2026-09-16-feishu-group-session-defaults-design.zh-CN.md)。

## 模型服务选择

发行版模型服务显示在所支持引擎的模型选项内，标明当前操作者的已登录、未登录、
登录中或登录失效状态。可选服务依赖缺失时显示「待安装」、发行版提供的安装指引和
「重新检测」按钮；声明支持安装的服务还显示「一键安装」。查看、选择或重新检测服务
均不安装软件。只有安装动作在 Hub 启动依赖安装，卡片轮询显示进度；完成后显示
登录入口，失败可重试，保留编辑草稿。
选择未登录的服务启动该服务 SDK 登录；有效登录直接复用。
卡片仅携带登录链接，不携带凭据或 challenge token。登录后展示完整可用的上游
模型与配置组合及思考强度。登录不保存或切换执行引擎；修改默认设置仍只影响新会话。
其他用户或共享执行 Principal 不会自动继承编辑者的个人凭据。
登录控件紧邻模型选择器并反映当前登录状态。选择服务入口或刷新登录时保留尚未保存的
模型和思考强度。已登录服务的模型紧接其入口集中展示，名称简洁且区分模型配置，
已有保存的模型引用保持可用。

## 发行版默认值迁移

发行版声明已退役默认 Profile 的精确旧值到新值映射。Bridge 负责受影响表、
参数化更新和事务。映射同时生效，保留无关设置与历史 Session 身份，并保持
幂等；迁移目标不能同时出现在迁移来源中。

## 管理界面语言

`/amux` 产品文案通过稳定键管理，
由公共中英文文案库提供。模板插入运行值，但不翻译用户填写的名称、路径、标识符、
诊断原文或 Agent 输出。文案库校验键与参数一致性，公共格式化机制负责复数与回退。

管理卡片使用 JSON 2.0 的**局部** `i18n_content`，回调提示使用 `i18n`，随查看者的
飞书/Lark 客户端语言显示。JSON 2.0 不支持全局 `i18n_elements`。
不支持的客户端语言回退英文。`/amux` 概览提供自动、英文和简体中文选项，按 Bot/用户持久化。
明确选择作用于服务端确认的私聊管理卡片和私聊会话卡片，包含按话题隔离和连续会话模式；
共享卡片和升级前的旧卡片保持按查看者语言
自动显示。重新发送 `/amux` 可让新卡片应用偏好。此偏好不改变 Agent 回复语言。权限卡片发送失败时，纯文本补发使用已保存语言；
自动模式下补发同时包含中英文，因为纯文本无法按查看者语言选择文案。
首次发送、原位更新、确认弹窗、异步结果和重启恢复遵循同一语言策略。
回调值和执行授权与语言无关。

依据：[飞书卡片多语言规范](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/configure-multi-language-content)
及 SDK 回调 `Toast.I18nContent` 契约。

平台无关的格式化模块位于 `internal/i18n`，Bridge 产品文案位于
`internal/bridge/locales/{en,zh-CN}.json`。新增文案时在两份资源中使用同一语义键，
将动态值作为模板参数传入。渲染接受明确的产品文案或原文字符串，不以用户内容查询翻译。
英文计数文案按需提供单数形式。测试比较两种语言的渲染结果，校验回调参数不变、卡片体积、
偏好持久化、共享卡片隔离以及更新失败后的补发。CLI 与桌面端覆盖另见
[产品语言模型](i18n-product-model.zh-CN.md)；Agent 生成内容保持原语言。

会话与子任务卡片同样使用按查看者语言显示的原生翻译，覆盖状态、耗时、用量标签、
问题与补充标题、计划、执行记录、处理过程与最终结果标题、完整输出入口及超长降级。
私聊会话卡片优先采用接收者已保存的语言偏好，自动模式跟随客户端语言；共享卡片始终
按各查看者的语言显示。每张 CardKit 卡片固定已验证的接收者和语言，重试及后续更新
不会把个人偏好应用到群聊。偏好变更作用于新卡片，历史卡片保留。
产品标题与 Agent 流式正文分开，CardKit 文本更新不会覆盖翻译或改写 Agent 原文。
活动区替换及旧路径的活动卡片保留同样的翻译；处理过程截断使用语言中立的省略符。
不追溯改写已发送的历史卡片。
